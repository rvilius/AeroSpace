## Command semantics

- **`aerospace move-workspace-to-monitor --workspace X EM` is the wrong primitive for "show workspace X on monitor EM without disturbing focus".** For an empty or never-placed X, its `workspaceMonitor` falls back to `mainMonitor` (`Workspace.swift:112`), so the command treats the PRIMARY as X's previous monitor and evicts it with a stub workspace (`MoveWorkspaceToMonitorCommand.swift:19-21`). It also no-ops once X is already remembered on the target (`:15`). The command relocates a workspace's monitor binding; it cannot set monitor M to display workspace W side-effect free.
- **Superseded 2026-09-17 by `workspace-groups`:** `setFocus` calls `activateWorkspaceGroupPeers` (`focus.swift`), so a single `workspace X` shows `X-2` on its pinned monitor, from any source (keybinding, Dock, menu bar), with one `focused-workspace-changed` event instead of two. The dance below is no longer used in `~/.aerospace.toml`. Caveat: `workspace X` is a no-op when X is already focused (`WorkspaceCommand.swift:30`), so re-pressing the key no longer repairs a displaced `X-2`; switch away and back. If that bites, call `activateWorkspaceGroupPeers` in that no-op branch.
- **(Historical) The working pattern was force-assignment plus a focus dance:** pin the workspace with `workspace-to-monitor-force-assignment` so `forceAssignedMonitor` wins and the `mainMonitor` fallback never applies, then run `['workspace X-2', 'workspace X']`, focusing the partner workspace (which renders it on its pinned monitor) and focusing back. It costs a brief focus flicker and only covers keybinding switches, not menu-bar clicks. This is how the secondary-monitor mirroring feature ships in `~/.aerospace.toml` (chezmoi source `dot_aerospace.toml.tmpl`).
